# RL_recsys: RL-дообучение GPT-2 рекомендера на KION

GPT-2 обучается предсказывать следующий объект по истории просмотров MTS KION, затем дообучается с помощью RL на награду от reward model (доля досмотра и её варианты): GRPO с точным KL к исходной модели, AWR, DPO/IPO, Best-of-N и CRR с критиком на логах. Для каждой награды считается аналитический оптимум π* ∝ π_ref·exp(r/β), чтобы отделить ограничения оптимизатора от ограничений самой награды.

## 📄 Полный отчёт: [report.pdf](report.pdf)

## Главный результат

Свежие пользователи тестовой недели 16–22.08.2021 (81 405 человек, которые не участвовали ни в отборе, ни в валидации), заранее объявленные кандидаты, единственная оценка. Для SFT абсолютные значения, для остальных разница с SFT и 95% CI парного bootstrap; proxy — длительность совпавших рекомендаций в % от SFT.

| Модель | NDCG@10 | Proxy@10 | NDCG@50 | Recall@50 | Длит., ч |
| --- | --- | --- | --- | --- | --- |
| SFT (абс.) | 0.1362 | 0.736 ч | 0.1777 | 0.3523 | 5.4 |
| Popular | −0.0048 | −14.4% | −0.0147 | −0.0290 | 4.9 |
| **AWR по длительности** | **+0.0010** [+0.0006; +0.0013] | **+2.6%** [+2.2; +3.0] | **+0.0012** [+0.0008; +0.0015] | +0.0008 [+0.0000; +0.0015] | 5.7 |
| CRR γ=0 | −0.0016 [−0.0024; −0.0008] | +5.7% [+5.0; +6.3] | −0.0020 [−0.0027; −0.0013] | −0.0044 [−0.0057; −0.0033] | 7.4 |
| GRPO R9, β=2 | −0.0000 [−0.0005; +0.0004] | +0.9% [+0.4; +1.4] | +0.0002 [−0.0003; +0.0006] | −0.0006 [−0.0013; +0.0002] | 4.8 |

Награда «доля досмотра» уводит рекомендации в короткий контент и значимо теряет и NDCG, и proxy, хотя обе reward model обещают рост. GRPO берёт 97–98% прироста награды, доступного при том же KL, так что компромисс задаёт награда, а не оптимизатор. Тест отбора на 10 тыс. пользователей, все варианты наград, CRR/AWR с критиком, персональная reward model и топ-50 — в отчёте.

## Данные

MTS KION, полный архив `data_original.zip` (~79 МБ) из [irsafilo/KION_DATASET](https://github.com/irsafilo/KION_DATASET), закреплённый на коммите и проверяемый по SHA-256 (оба значения в `rl_recsys/data.py`). Данные в репозиторий не входят. `run.py` скачивает архив в `data/raw/` сам, можно и заранее:

```bash
python -m rl_recsys.data
```

## Воспроизведение

Нужны Python 3.12+, `curl` и GPU (CUDA или Apple MPS; устройство выбирается автоматически, `device` в конфиге).

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python run.py --smoke          # проверка всего конвейера на 3 тыс. пользователей, out_smoke/
```

Все прогоны отчёта на полных данных (850 тыс. пользователей) в том порядке, в каком они делались:

```bash
scripts/reproduce_full.sh
```

Отчётные прогоны шли на ноутбуке с RTX 4060 Laptop: SFT около 40 минут, каждая reward model около 5 минут, RL-прогон на 4 000 шагов 3–5 минут, весь скрипт — около ночи. Каждая стадия пропускается, если её артефакт уже есть, а RL-прогоны продолжаются с последнего чекпойнта, поэтому после прерывания достаточно запустить ту же команду. Результаты пишутся в `out_full/`: `results_test_*.csv` (тест отбора, 10 тыс. пользователей, с CI против SFT), `results_test_at50.csv`, `results_fresh_test.csv` (свежие пользователи), `tilted_*.csv`, `objective_gap.csv`, `rm_p_quality.json`, `within_user_ci.json`, логи обучения в `runs/*/log.jsonl`.

Отдельные стадии и прогоны:

```bash
.venv/bin/python run.py --full --stop-after rm                                     # данные, SFT, RM-A, RM-B
.venv/bin/python run.py --full --stop-after rl --runs grpo_r9_b2.0_fix,awr_hours_g1  # RL-прогоны
.venv/bin/python run.py --full --runs awr_hours_g1 --final awr_hours_g1              # тест
.venv/bin/python scripts/eval_fresh.py --out out_full                                # свежие пользователи
```

`--full` берёт всех пользователей и пишет в `out_full/`. Без него `run.py` работает на подвыборке 200 тыс. пользователей (`out/`), на которой в начале шёл отбор вариантов (прогоны без суффикса `_fix`). Все прогоны описаны в `config.json` → `rl.runs`.

## Протокол

- **Сплит по времени.** Словарь, SFT, reward model и RL-контексты обучаются на событиях до 09.08.2021. Валидация (ранняя остановка, выбор β и вариантов) — неделя 09–15.08, тест — 16–22.08. Цель — все объекты целевой недели, уже просмотренное исключено из рекомендаций.
- **Оценка.** 10 тыс. случайных пользователей с историей и хотя бы одной целью (тест отбора) плюс все остальные пользователи тестовой недели для однократной проверки финальных кандидатов. Разницы с SFT — парный bootstrap по пользователям.
- **Одинаковые условия RL.** Одна SFT, одни reward model, 4 000 шагов, батч 256, lr 3e-5, dropout выключен во время RL.

## Структура

| Путь | Что там |
| --- | --- |
| `run.py` | точка входа: данные → SFT → RM-A / RM-B → RL-прогоны → тест |
| `config.json` | гиперпараметры и список всех RL-прогонов |
| `rl_recsys/data.py`, `sequences.py` | загрузка KION, последовательности пользователей, словарь, сплиты |
| `rl_recsys/gpt.py`, `models.py` | SFT GPT-2 (2 слоя, 128-мерные эмбеддинги), рекомендации, Popular |
| `rl_recsys/reward.py` | RM-A: GPT-2 от SFT с головами досмотра, возврата и склонности |
| `rl_recsys/rm_b.py` | RM-B: независимая LightGBM, только для оценки |
| `rl_recsys/rm_personal.py` | RM-P: RM-A с признаками пользователя, изотоническая калибровка |
| `rl_recsys/rl.py`, `crr.py` | GRPO, AWR, DPO/IPO, Best-of-N, CRR с критиком, награды R1–R9 |
| `rl_recsys/evaluate.py`, `metrics.py` | NDCG/Recall/MAP, proxy длительности, покрытие, многошаговая генерация |
| `scripts/tilted.py`, `objective_gap.py` | аналитический оптимум π* и доля прироста, которую берёт обученная политика |
| `scripts/eval_at50.py`, `eval_fresh.py`, `within_user_ci.py` | топ-50, свежие пользователи, Spearman внутри пользователя |
| `scripts/reproduce_full.sh` | все прогоны отчёта на полных данных |
| `report.pdf` | отчёт |
